# Orna Helper（Android 自動化外掛範例）

一個以「無障礙服務（Accessibility Service）模擬點擊」＋「MediaProjection 螢幕擷取」＋「色塊判讀」為基礎的 Android 遊戲自動化範例專案。核心是一個四狀態的畫面辨識迴圈：**地圖畫面**（框選範圍內找怪物並點擊）→ **確認介面**（點「戰鬥」）→ **戰鬥畫面**（重複點擊攻擊格）→ **結算畫面**（點「繼續」回到地圖），並在地圖畫面時定期長按「物品」按鈕自動回復 HP/MP。

## ⚠️ 使用範圍（請務必遵守）

**這個工具只設計給你自己完全掌控、允許自動化操作的私有／單機測試環境使用**（例如你自架的私服、本機模擬的遊戲邏輯）。

**請勿**將它用於：
- 連線任何官方伺服器、正式服務，或任何服務條款禁止外掛／自動化操作的線上遊戲——這通常會違反服務條款並導致帳號被封鎖，也會破壞其他玩家的遊戲體驗。
- 任何你沒有明確授權自動化的系統。

工具本身完全在裝置端運作（讀取畫面像素、模擬點擊），不會連線任何伺服器，也不包含任何針對特定遊戲伺服器協議的破解或逆向邏輯——它是通用的「看畫面、按按鈕」自動化框架，具體行為完全取決於你如何校準。

## 架構

```
app/src/main/java/com/ornahelper/autoplay/
├── data/
│   ├── Models.kt            # BotConfig / ScreenRect / CalibratedRegion 等資料模型
│   └── ConfigRepository.kt  # 設定的 JSON 持久化（SharedPreferences）
├── engine/
│   ├── BarReader.kt         # 用色彩距離判讀血條百分比 / 區域是否變化
│   └── BotEngine.kt         # 主迴圈：讀血條 → 判斷是否補藥／攻擊／移動
├── service/
│   ├── OrnaAccessibilityService.kt  # 只做一件事：dispatchGesture 模擬點擊／長按
│   └── OrnaBotService.kt            # 前景服務：畫面擷取、懸浮控制面板、校準選單、驅動 BotEngine
└── ui/
    ├── MainActivity.kt          # 權限引導、閾值設定
    └── CalibrationOverlayView.kt # 單次框選/點選用的全螢幕擷取畫布
```

**為什麼不硬編碼座標／顏色？** 因為每個人的裝置解析度、遊戲 UI 版面、私服畫面都不同，硬編碼對你的環境不見得有效。所以所有「怪物在哪」「按鈕在哪」都透過懸浮面板上的**校準選單**（拖曳框選 / 點選）由你自己指定，存成 JSON 設定檔。

## 判讀原理（重要限制）

`BarReader` 不是 OCR，而是簡單的色彩比對：
- **目前在哪個畫面**：地圖與戰鬥各自有自己獨立的判斷依據，確認／結算則共用同一種判斷方式，而且**判斷順序刻意把地圖／戰鬥放在前面**：
  - **地圖／戰鬥**（優先判斷）：校準時各框選一個「只有該畫面才會出現」的固定小區域（`mapAnchor` / `battleAnchor`），記錄該區域當下的平均顏色。執行時分別獨立比對這兩個區域目前的顏色跟各自校準時的顏色距離，只要距離在容忍度（`stateAnchorTolerance`）內就判定是該畫面；兩者都在容忍度內的機率極低，真的同時成立時取距離較近的一個。
  - **確認戰鬥／結算**（次要判斷，只有地圖/戰鬥都判斷不出來時才檢查）：不跟任何校準顏色比對距離，而是直接判斷「戰鬥」／「繼續」按鈕當下的顏色是不是「看起來像綠色」（用 HSV 色相/飽和度/亮度判斷，`BarReader.regionLooksGreen`）。
  - **為什麼順序很重要**：很多遊戲的地圖地面本身就是綠色，如果先檢查「按鈕位置是不是綠色」，站在地圖上時，「戰鬥」／「繼續」按鈕座標剛好疊在綠色地面上的機率很高，會被誤判成確認／結算畫面。把地圖／戰鬥的獨立選擇區判斷放在前面，只要其中一個明確匹配就直接採用，不會再去看那兩個按鈕座標的顏色，從根本上避開這個誤判；綠色判斷只在「地圖、戰鬥都對不上」時才啟用，作為確認／結算這兩個瞬時畫面的偵測手段。
- **怪物偵測**：校準時框選「怪物出現的橢圓範圍」，系統記錄該範圍的平均顏色當作背景色；執行時在範圍內做粗略網格掃描，找出顏色明顯偏離背景色的格點（也就是怪物圖示），並把相鄰的格點分群（flood fill），取「格點數最多的那一群」（也就是畫面上最大/最明顯的怪物）的重心當作點擊座標——同時有多隻怪物時也能準確點在其中一隻身上，而不是點在它們中間的空地。
- **物品自動回復**：地圖畫面時，系統會定期（可調整間隔）長按「物品」按鈕 3 秒，觸發遊戲內建的自動回復。

這代表**每次遊戲改版、UI 版面調整、裝置換了、解析度變了，都需要重新校準**。

## 使用步驟

1. 用 Android Studio 開啟本專案（需要 Android SDK，`compileSdk 34` / `minSdk 26`）。
2. 安裝到裝置後開啟 App，依序：
   1. 授予「顯示在其他應用程式上層」（懸浮視窗）權限。
   2. 到「無障礙設定」啟用 Orna Helper 的無障礙服務（用於模擬點擊／長按）。
   3. 點「授權畫面擷取並啟動服務」，系統會跳出畫面錄製授權對話框，同意後背景服務啟動，畫面上會出現一個可拖曳的小懸浮面板。
3. 切換到你的私服／測試環境畫面，點懸浮面板上的「校準」會打開一個**校準選單**（同樣是小懸浮視窗，不會擋住遊戲畫面），列出 7 個可校準項目，各自獨立、**可任意順序、分開進行**：
   - 怪物範圍、地圖錨點、物品鈕：在地圖畫面上就能校準。
   - 戰鬥錨點、戰鬥攻擊格：**先在遊戲裡正常手動操作**，打一場戰鬥切到戰鬥畫面，再回來點選單裡對應項目。
   - 戰鬥確認鈕：先手動點一隻怪物，切到確認介面，再點選單裡的項目。
   - 結算繼續鈕：先手動打完一場戰鬥，切到結算畫面，再點選單裡的項目。

   點選單裡的項目後，畫面才會短暫出現全螢幕的框選/點選介面，完成那一個動作（拖框或點一下）後會立刻儲存、立刻關閉，回到可以正常操作遊戲的狀態；選單本身會留在畫面上，方便你切換畫面後繼續校準下一項。每一項旁邊會顯示「（已校準）」或「（未校準）」，可以隨時重新校準單一項目，不需要每次都全部重做。
4. 回到 App 主畫面調整「偵測間隔」「自動回復物品間隔」「最長執行時間」等參數並儲存。
5. 點懸浮面板上的「啟動」開始自動打怪／自動回復；再點一次即可停止。懸浮面板文字會顯示目前判定所在的畫面（地圖／確認戰鬥／戰鬥中／結算畫面／辨識中）。

## 安全機制

- 可設定「最長執行時間」，時間到自動停止。
- 懸浮面板隨時可見、可一鍵停止（不需要回到 App）。
- 停止畫面錄製（例如系統通知列收回錄製）會自動停止整個機器人迴圈。

## 已知限制／可以擴充的方向

- 畫面辨識完全靠單點／小區域顏色比對，若地圖或戰鬥錨點的顏色跟其他畫面某處顏色太接近，仍有可能誤判；建議選比較獨特、飽和度高、不太可能在別的畫面同一位置出現的顏色當錨點。
- 色彩比對對於動態光影、半透明特效較敏感，之後可以考慮加入模板比對（bitmap 差異比對）取代單純顏色距離，準確度會更高但運算量也更大。
- 分群目前用的是校準時取樣網格上的 8 連通 flood fill，網格間距會隨橢圓範圍大小自動調整；如果怪物圖示很小或範圍框得特別大，網格可能太粗而漏掉小怪，可以調整 `minMonsterClusterSamples`（最小群集格點數）或把範圍框小一點來改善。
